# 领域约定

暴雨预警版本分发中枢围绕气象预警、订正版本与渠道回执保存可核对的业务记录。外部主体使用不含真实身份信息的稳定引用编号，时间采用带偏移量的 ISO 8601 字符串，材料只保存受控引用和 `sha256` 摘要。

## 交换事件

交换事件包含 `event_id`、`event_type`、`subject_ref`、`source_ref`、`occurred_at`、`source_sequence`、`payload_digest` 和 `payload`。`event_type` 取值 `ISSUE`（发布）、`CORRECT`（订正）、`CANCEL`（解除）。来源序号只在同一来源内递增，接收方必须保留原始发生时间，不得用到达时间覆盖。示例内容仅用于说明字段形状，不代表真实人员、机构或业务结论。

`payload_digest` 是对 `payload` 的规范 JSON（键按字典序、无空白、中文不转义）计算的 `sha256:<64位十六进制>`，接收方逐条核验，不一致即拒绝且不落库。`contracts/event.example.json` 给出一条可通过核验的完整示例。

发布与订正的 `payload` 必须包含 `alert_level`、`rain_range`、`hourly_intensity`、`regions`、`valid_from`、`valid_until`；订正是全量快照，直接构成新一版。解除的 `payload.regions` 为空时作用于该主题全部仍在生效的行政区。

## 判定与版本

- 每个被应用的事件追加一个不可变版本，版本号按主题内递增；事件、版本、生效片段、确认记录只追加，数据库触发器拒绝改写与删除。
- 同一 `event_id` 重复投递返回首次处理结果；摘要不同的同号事件按冲突拒绝。
- 迟到消息（来源序号不高于该来源已应用序号，或 `occurred_at` 早于现行版本决定时间）只登记为 `LATE`，绝不覆盖较新的决定。
- 主题解除后即关闭，后续订正按冲突拒绝；重复发布同一主题同样按冲突拒绝。

## 生效片段

每次版本触及的行政区都追加一条生效片段，记录形成依据（`formed_by_event_id`）与生效起点。订正缩小的区域会得到撤销片段（`cancel_reason=SCOPE_REDUCED`），解除消息产生 `EXPLICIT` 撤销片段。任一时刻某地区的状态由当时最新片段与版本时效窗口共同决定：`SCHEDULED`（未到生效起点）、`ACTIVE`、`EXPIRED`（到达 `valid_until`，左闭右开）、`CANCELLED`。

## 时间

所有业务时间必须带时区偏移；缺失偏移一律拒绝。时效比较按绝对时刻进行，跨越午夜的窗口以来报原始偏移为准，展示时保留原始字符串，不做本地时区换算。

## 送达

每个生效片段（含撤销片段）按 (地区, 渠道, 岗位) 从接收岗位目录生成唯一送达记录，渠道为 `sms`、`broadcast`、`terminal`。渠道尝试逐条留痕，失败按退避重试，超过上限进入 `EXHAUSTED`，人工补发可重新排入派发；补发与重试都不产生重复送达记录。确认按 `receipt_id` 幂等，重复回执返回首次确认。服务重启时回收中断在 `SENDING` 的记录并继续派发。
